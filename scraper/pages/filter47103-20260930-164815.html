Search Query Syntax Instructions

When multiple keywords are entered, for example logo, design, website, the search engine finds projects containing any of these words in the title, description, or skills. To customize the search scope, use the checkboxes under 'Advanced Keywords Options' to enable/disable searching within title, description, or skills fields.

All Keywords Search

To find projects that contain all of your keywords, use the AND operator between words:

  • logo AND design AND website - Must include all three words
  • react AND developer - Must include both "react" and "developer"

Wildcards

Use * to match variations of a word:

  • develop* - Matches "developer", "development", "developing", etc.

Exact Phrases

Use quotes for exact phrase matches:

  • "website design" - Finds the exact phrase "website design"

Must-Include Terms

Use the + symbol before any word that must be present. For example:

  • +website +design logo - Must include both "website" and "design", "logo" is optional

Excluded Terms

Use the - symbol to exclude specific terms. For example:

  • +developer -wordpress - Must include "developer" but exclude projects with "wordpress"

Advanced Search Mode provides the same functionality as Basic Search, but uses a text field instead of tags for greater control and visibility. This makes it easier to:

  • Write and edit complex queries
  • See your entire search at once
  • Copy and save queries for later use
  • Fine-tune your search terms

All instructions from Basic Search work in Advanced Mode:

  • AND operator: logo AND design AND website
  • Must-include (+): +website +design logo
  • Exclude (-): +developer -wordpress
  • Wildcards (*): develop*
  • Exact phrases: "website design"

Default Search Behavior

By default, all terms are optional. By entering app design mobile you'll find projects that contain any of these words.

More Advanced Operators

Advanced Mode adds these powerful features:

Search by Field

You can search within specific fields using field prefixes:

Available fields:

  • title: - Search in project titles
  • description: - Search in project descriptions
  • skills: - Search in required skills

Examples:

  • title:wordpress AND skills:php - Find WordPress in projects title and PHP in Skills
  • description:"mobile app" AND NOT skills:flutter - Find "mobile app" in projects descriptions and Skills doesn't contains Flutter
  • skills:(react OR vue) AND title:frontend - Find frontend in projects title and Skills contains React or Vue

Boolean Operators

You can use AND, OR, NOT for complex queries:

Examples:

  • mobile OR web
  • ui AND design NOT wordpress

Grouping Terms

Use parentheses to group terms and create sub-queries:

Examples:

  • (frontend OR backend) AND (react OR node)
  • (UI OR UX) AND mobile AND NOT (wordpress OR shopify)

Pro Tips

  • Always use parentheses when combining different operators
  • You can mix basic and advanced syntax: +react (vue OR angular)
  • Group similar alternatives within parentheses
  • Start simple and add complexity as needed

Understand how 'Freelancer Location' works

US/UK-based special feeds

There is a specific U.S. feed available to US-based freelancers only and a specific U.K. feed available to UK-based freelancers only.

Clients in the USA (only) can restrict their job posts to be visible to freelancers in the USA only, and clients in the UK (only) can restrict their job posts to freelancers in the UK only.

We added filter attributes to manage how to display projects from these special feeds. Now you can include (by default), exclude, or show only projects from these feeds.

Freelancer Location

Clients from any country can set a location preference to any country. This doesn't mean that only freelancers from that country will see the projects, but it means that client might give priority to freelancers from that country.

We added filter attributes for better control over this behavior.

When you select a country in 'Freelancer Location' filter, it will show only projects where client has set this country as Location in Preferred qualifications, and hide all other projects where it's not set. Use 'Include projects without preferred freelancer location' to also show jobs without any Location qualifications. If no Freelancer Location is selected, this option does not narrow the results.

Filter by lower range value

Some Upwork jobs post a budget range instead of one figure — an hourly job at $30–$80/hr, say, or a fixed-price job with a low and high estimate. This setting decides which end of that range your minimum budget has to meet.

Off (default) — match either end

A job shows if either end of its range meets your minimum, so a range that starts below your minimum but reaches above it still gets through.

On — match the lower end

A job shows only if the lower end meets your minimum, which drops jobs that reach it only at the top of their range.

Example

Say your minimum hourly rate is $50/hr:

Job posted at Off (default) On
$30–$80/hr Shown ($80 ≥ $50) Hidden ($30 < $50)
$60–$120/hr Shown ($60 ≥ $50) Shown ($60 ≥ $50)

Works the same for hourly and fixed-price ranges. With no minimum budget set, it has no effect.

Include clients without sufficient history

Upwork only reports a client's spend, hires, rating, and reviews once that client has run some contracts. Brand-new clients have no track record yet — Vollna treats them as having no sufficient history. This setting decides whether those clients still reach you once you've set client-quality filters.

On (default) — keep no-history clients

A client with no track record is shown even when you've set a minimum Total spend, Hires, Rating, or Reviews. Those thresholds are skipped for them, because there's no data to check against — so a brand-new client can appear alongside your minimum-spend results.

Off — require enough history

A client must have enough history to be judged. Anyone Upwork reports no data for is hidden, so only clients whose figures meet your thresholds get through.

This only affects clients with missing data. A client with a recorded spend below your minimum is always hidden — whether this is on or off.

Example

Say your minimum Total spend is $1,000:

Client On (default) Off
New client, no history Shown (no data to check) Hidden
Spent $400 Hidden ($400 < $1,000) Hidden ($400 < $1,000)
Spent $5,000 Shown ($5,000 ≥ $1,000) Shown ($5,000 ≥ $1,000)

Applies to every client-history filter — Total spend, Hires, Rating, Reviews, and more. With no client filters set, it has no effect.
